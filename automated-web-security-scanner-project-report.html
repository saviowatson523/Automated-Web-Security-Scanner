1. Introduction

Web security misconfigurations are among the most common vulnerabilities in modern web applications. HTTP security headers are a lightweight but powerful mechanism that instruct browsers to enforce security policies — yet they are frequently absent or misconfigured in production environments.

This project delivers an Automated Cybersecurity Web Scanner that enables any user to analyse the security posture of a target website in seconds, without requiring specialist knowledge or command-line tools. The application is built entirely in Python and exposed through an interactive browser-based interface powered by Streamlit.

2. Objectives

  • Automatically check HTTP security headers, HTTPS/SSL configuration, and CORS settings of any URL.
  • Present findings with clear Pass / Warning / Fail verdicts and actionable recommendations.
  • Compute an overall security score and summarise the site's security posture.
  • Allow users to export scan results as CSV or JSON for reporting or further analysis.
  • Keep the tool accessible — no installation of specialist security software required.

All logic resides in a single file, app.py, which is intentionally kept minimal. The scanner makes one HTTP GET request to the target URL, captures the response headers, then passes them through nine independent check functions. Each function returns a structured dictionary with four keys: check, status, detail, and recommendation.

6. Application Workflow

  1. The user enters a target URL in the Streamlit input form.
  2. The normalize_url() function ensures a valid scheme (https://) is present.
  3. The fetch_headers() function issues an HTTP GET request (timeout: 10 s), follows redirects, and captures the final response headers. SSL and connection errors are caught and surfaced as structured findings.
  4. Nine check functions are invoked sequentially. Each inspects the relevant header value and returns a result dictionary.
  5. The UI renders a security score (Pass count ÷ total × 100), four summary metrics, a per-check expandable detail panel, and download buttons for CSV and JSON exports.

7. Key Code Components

7.1 URL Normalisation

def normalize_url(url: str) -> str:
    url = url.strip()
    if not url.startswith(("http://", "https://")):
        url = "https://" + url
    return url

7.2 Header Fetching with Error Handling

def fetch_headers(url, timeout=10):
    try:
        resp = requests.get(url, timeout=timeout,
                            allow_redirects=True, verify=True)
        return resp, resp.headers, resp.url, None
    except requests.exceptions.SSLError as e:
        return None, {}, url, f"SSL Error: {e}"
    except requests.exceptions.ConnectionError as e:
        return None, {}, url, f"Connection Error: {e}"
    except requests.exceptions.Timeout:
        return None, {}, url, "Request timed out."

7.3 Example Check — HSTS

def check_hsts(headers):
    val = headers.get("Strict-Transport-Security", "")
    if not val:
        return {"check": "HSTS", "status": "Fail", ...}
    max_age = parse_max_age(val)
    if max_age < 31536000:
        return {"check": "HSTS", "status": "Warning", ...}

11. Limitations

  • The scanner performs passive analysis only — it inspects HTTP response headers and does not perform active exploitation or deep vulnerability scanning.
  • JavaScript-rendered content and single-page applications may present different headers than static pages; the scanner evaluates only the initial HTTP response.
  • Sites that block automated HTTP requests (via CAPTCHAs, WAFs, or IP filtering) may return incomplete or error results.
  • CORS analysis is limited to the Access-Control-Allow-Origin header; complex pre-flight scenarios are not simulated.

12. Future Enhancements

  • Add cookie security checks (Secure, HttpOnly, SameSite flags).
  • Integrate DNS-based checks (DNSSEC, SPF, DMARC, DKIM).
  • Support batch scanning of multiple URLs from an uploaded file.
  • Add SSL certificate expiry date and cipher strength checks.
  • Integrate with the OWASP Top 10 mapping to contextualise each finding.
  • Add historical scan comparison to track security posture over time.

13. Conclusion

The Automated Cybersecurity Web Scanner successfully meets all stated objectives. It provides a fast, accessible, and informative way to evaluate the security header configuration of any publicly reachable web server. Built with fewer than 400 lines of Python and two dependencies, it demonstrates that meaningful security tooling does not require complex infrastructure.

The tool is well-suited for web developers, system administrators, and security students who need a quick first-pass assessment of a site's defensive HTTP headers, and it produces structured, shareable output suitable for inclusion in security audits or reports.

Ethical Notice: This tool is intended for educational purposes and authorised security testing only. Always obtain explicit permission before scanning websites you do not own.
